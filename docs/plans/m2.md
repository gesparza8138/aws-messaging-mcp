## 2. Design

### 2.1 Shared SES stack — `infra/ses-domain.yaml` (us-west-2, once)

- `AWS::SES::EmailIdentity` for `gabriel-esparza.com` (Easy DKIM RSA-2048), `MailFromAttributes` → `bounce.mcp.gabriel-esparza.com`, `ConfigurationSetAttributes` unset (per-stage sets below).
- Route 53 records: 3 DKIM CNAMEs in the **root zone** (zone id from SSM `/messaging-mcp/root-zone-id`), `_dmarc` TXT (`p=quarantine; rua=mailto:esparza.gabriel@gmail.com; adkim=s; aspf=r`), root SPF TXT (`v=spf1 -all`), and MAIL FROM `MX`/`TXT` in the `mcp` zone.
- `infra/root-dns.yaml`: remove the carried-over GoDaddy `MX` pair (owner decision).
- Outputs → SSM: `/messaging-mcp/ses/identity-arn` for IAM conditions.

### 2.2 `app.yaml` additions (both stages)

- `RateLimitTable` (DynamoDB on-demand, PK `pk`, TTL `expires_at`).
- `SesConfigurationSet` + `EventDestination` (send/delivery/bounce/complaint/reject → CloudWatch Logs group `/aws-messaging-mcp/<stage>/ses-events`, 14/90 d).
- Execution role: `ses:SendEmail`/`SendRawEmail` on the identity + config set ARNs with `Condition: StringEquals ses:FromAddress ∈ SesSenderAddresses`; `dynamodb:{Get,Put,Update}Item` on the table.
- Parameters → env: `SesSenderAddresses`, `SesReplyTo`, `RecipientAllowList` (dev only; empty = off), `RateLimitPerHour`, `RateLimitPerDay`, `MaxRecipients`, `EmailMaxRawBytes`.
- Dev-only (`IsDev`): confidential `ci` app client with `USER_PASSWORD_AUTH` for e2e (PRD §11.3).

### 2.3 Application (Go)

```text
internal/
├── schemas/ses.go        # input structs mirroring sesv2 SendEmail (PascalCase JSON tags, unknown fields rejected)
├── guardrails/
│   ├── allowlist.go      # sender + recipient allow-lists (email; phone later)
│   ├── ratelimit.go      # sliding windows in DynamoDB behind a small interface, frozen-clock tests
│   └── decision.go       # Decision → ServerMetadata.guardrails
├── mcpserver/
│   └── ses.go            # ses_send_email (Simple | Raw), ses_list_email_identities, ses_get_account
└── awsclients/           # SDK v2 client construction + ClientError → tool error with Code/Message
```

Rules (PRD §5.1): server injects `ConfigurationSetName` and default `ReplyToAddresses`; rejects `FromEmailIdentityArn`, `FeedbackForwardingEmailAddress`, `ListManagementOptions`; exactly one of `Content.Simple`/`Content.Raw`; `Raw` parsed (`net/mail`) for `From` (allow-list) and decoded size ≤ `EmailMaxRawBytes`; ≤ `MaxRecipients`; `DryRun` returns `{"WouldCall": {...}, "ServerMetadata": {...}}`. Scopes: `msg/email:send`, `msg/read`.

### 2.4 Tests

- Unit: schema validation matrix, allow-lists, rate-limit math (in-memory fake of the DynamoDB interface, frozen clock), MIME parsing, error mapping — `internal/guardrails` at 100 % (added to `scripts/check_coverage.sh`).
- Integration: `tools/call ses_send_email` through the auth chain with a fake SES client (DryRun and mocked-send paths), go-sdk client over `httptest`.
- Contract: reflection over `sesv2.SendEmailInput` — every schema field exists in the SDK struct with a compatible type; required API members are required-or-injected.
- E2E (`go test -tags e2e ./e2e/...`, `make e2e`, CI after dev deploy): CI user token via `USER_PASSWORD_AUTH`; `DryRun` call; one real email to `esparza.gabriel@gmail.com`; poll the SES event log group for a delivery event (bounded; skip on carrier delay).

### 2.5 Docs

`docs/tools/ses_send_email.md`, `ses_list_email_identities.md`, `ses_get_account.md` generated by `scripts/gen-tool-docs.py` from the tool schemas (CI drift check in `docs.yml`); `docs/testing.md`; `aws-prerequisites.md` §1 rewrite (M2-5); PRD §5.3/§8/§11 corrections; decision log.
