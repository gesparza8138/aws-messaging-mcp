## 2. Design

### 2.1 Infra

- **`infra/eum.yaml` (new, shared, workstation-deployed like `ses-domain`)**:
  the toll-free `AWS::SMSVOICE::PhoneNumber` (US, `[SMS, MMS]`, `TOLL_FREE`,
  transactional, two-way off, deletion-protected, `Retain`) and the
  `AWS::SMSVOICE::ProtectConfiguration` (allow `US` only). Outputs → SSM
  (`/messaging-mcp/eum/phone-arn`, `phone-id`, `phone-number`,
  `protect-configuration-id`) for IAM conditions and stack parameters. One
  number serves both stages (cost: ~$2/month total).
- **`infra/app.yaml` (per stage)**: `AWS::SMSVOICE::ConfigurationSet`
  (`aws-messaging-mcp-<stage>-sms`) with an inline CloudWatch Logs event
  destination → `/aws-messaging-mcp/<stage>/eum-events` (ALL text + media
  events), protect configuration attached; **media bucket**
  (`aws-messaging-mcp-media-<account>-<stage>`, private, no CloudFront —
  PRD hard rule — 7-day lifecycle, EUM service principal granted read via
  bucket policy scoped by `aws:SourceAccount`); Lambda role grants:
  `sms-voice:SendTextMessage`/`SendMediaMessage` on the phone-number ARN
  (from SSM) + configuration-set ARN, `sms-voice:DescribePhoneNumbers`,
  `s3:PutObject/GetObject` on the media bucket, `logs:FilterLogEvents` on the
  EUM event group. New parameters: `SmsMaxPrice` (default `0.05`),
  `OriginationIdentity` (the shared number, resolved from SSM by the deploy
  workflow).
- **Account-level spend limit** (`set-text-message-spend-limit-override
  --monthly-limit 20`): one-time CLI step in the prerequisites doc (no CFN
  surface).
- **Edge**: `/opt-in` exemption in the CloudFront function (both stages);
  static page served by `internal/httpapi` (text per prerequisites §2.2).

### 2.2 Tools (all `msg/sms:send` unless noted)

| Tool | Mirrors | Notes |
| --- | --- | --- |
| `sms_send_text_message` | `SendTextMessageInput` | Server-injected: `ConfigurationSetName`, `ProtectConfigurationId`, `OriginationIdentity` default; `MaxPrice` capped at the stack ceiling; `MessageType` defaults `TRANSACTIONAL` |
| `sms_send_media_message` | `SendMediaMessageInput` | `MediaUrls` must point into the stage's media bucket; optional `MediaUpload {FileName, ContentType, Base64Content}` convenience uploads (≤ 5 MB, jpeg/png/gif) and substitutes the `s3://` URL |
| `sms_describe_phone_numbers` | `DescribePhoneNumbersInput` | `msg/read` |
| `sms_get_message_status` | — (event lookup, M3-3) | `msg/read`; input `{MessageId}` |

Guardrails (all in `internal/guardrails`, 100 % coverage): recipient
allow-list in E.164 (same `RecipientAllowList` parameter, comma list mixes
emails and numbers; matcher splits by shape), `MaxPrice` ceiling, media
type/size, media-bucket-only `MediaUrls`, shared sliding-window rate limiter
(same DynamoDB table, per-tool keys). `DryRun` per M3-2.

### 2.3 Code layout

`internal/schemas/eum.go` (+ contract test reflecting over
`pinpointsmsvoicev2.SendTextMessageInput` etc.), `internal/awsclients` gains an
`EUM` interface + `CloudWatchLogs` reader, `internal/mcpserver/eum.go` handlers
mirroring `ses.go`, settings for the new env vars. E2E extends the existing
suite: one real SMS and one MMS to `E2E_TEST_PHONE` (GitHub dev secret —
already provisioned for in `setup-github.sh`), delivery check skips on carrier
delay exactly like email.
